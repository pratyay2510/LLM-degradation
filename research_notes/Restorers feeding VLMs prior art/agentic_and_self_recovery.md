# Agentic / tool-calling restoration for MLLM understanding, and unified-MLLM self-recovery ("generate-then-reason")

Scope: Jan 2024 – Sep 2026 (queried 2026-09-23). Venue verification method is stated per entry: "arXiv comment line" = the Comments field on arxiv.org/abs; "CVF" = openaccess.thecvf.com page returned HTTP 200 and/or title present in the CVPR/ICCV index dump; "OpenReview" = api2.openreview.net search returned a note with the stated venue; "ICML virtual" = icml.cc/virtual/2026 paper search; "S2" = Semantic Scholar API. Anything I could not confirm from a proceedings page or the arXiv comment line is labeled **UNVERIFIED**.

Threat levels are against the user's three formulations:
- **F1** answer identifiability from y via the MLLM's answer distribution over measurement-consistent posterior samples x ~ p(x|y) (measurement-determined / prior-determined / undetermined).
- **F2** hypothesis-conditioned evidence: p(y | q, a) per candidate answer via a text-conditioned diffusion inverse solver; Bayes factor selection.
- **F3** measurement-consistent self-recovery inside a unified MLLM (Robust-U1/BAGEL-style) with a controlled internal-vs-external comparison.

## KQ1. Which agent frameworks use restoration specifically to improve MLLM QUESTION ANSWERING, and how do they decide when to restore?

### Takeaway
Only two agent systems in the window restore *in service of a question*: DocIntent (arXiv-only, Aug 2026; MLLM self-judges answerability, then calls document restorers, with an MLLM before/after comparison for rollback) and, on the unified-model side, CLEAR (arXiv-only; learned `<image_restore>` trigger, KQ3). Every venue-verified restoration agent (RestoreAgent NeurIPS'24, AgenticIR ICLR'25, JarvisIR CVPR'25, 4KAgent NeurIPS'25, HybridAgent CVPR'26, Restore-R1 CVPR'26-Findings, TIR-Agent ECCV'26-likely, MAIR IJCV'26, IAMAgent TIP'26) optimizes image quality (IQA / PSNR / MLLM-perceptual reward), not answer correctness, and decides "when to restore" from degradation classifiers or IQA scores, never from answerability. None uses a forward model, data consistency, posterior sampling, or multiple restorations, and none propagates uncertainty to an answer.

### Cited Findings

#### DocIntent — in depth (the paper a reviewer will cite)
- Bibliographic: "DocIntent: Answerability-Guided Agentic Restoration for Real-World Document Visual Question Answering", Zihan Huang, Shihang Wu, Junle Liu, Peirong Zhang, Yongxin Shi, Xuhan Zheng, Lianwen Jin (South China Univ. of Technology). arXiv:2608.29037v1, 29 Aug 2026, "25 pages, 14 figures"; **no venue in the comment line; UNVERIFIED venue (arXiv-only as of 2026-09-23)**; S2 lists 0 citing papers — [arXiv abs](https://arxiv.org/abs/2608.29037); [arXiv HTML](https://arxiv.org/html/2608.29037); [S2 citations](https://api.semanticscholar.org/graph/v1/paper/arXiv:2608.29037/citations?fields=title,venue,year,externalIds&limit=500)
- Claimed contribution: "To the best of our knowledge, we are the first to explore the value of agentic restoration for document restoration and real-world degraded document VQA"; a "training-free Answerability-Guided Agentic Restoration framework" that "first assesses question answerability, then identifies task-relevant degradations and selectively invokes restoration tools", with "no additional pretrained degradation classifier or image quality assessment model" — [arXiv HTML](https://arxiv.org/html/2608.29037)
- **How answerability is assessed: pure MLLM self-judgment via prompting.** "The MLLM first analyzes the image in conjunction with the question to determine whether the question can be answered directly from the current image. If so, it generates the answer directly without triggering restoration. Otherwise, the MLLM identifies which degradations prevent it from answering and selects the most severe one whose corresponding tool is available." Algorithm 1: "The functions Analyze, SelectTool, Compare, and Answer are all implemented by the MLLM." No probe, no IQA model, no confidence/entropy measurement — [arXiv HTML, §3.1 and App. B](https://arxiv.org/html/2608.29037)
- **Restoration tools (regression, not diffusion, not physics):** Group 1 (main) = DocRes (CVPR 2024 generalist document restorer) for deblurring, dewarping, deshadowing, appearance enhancement; UniDemoiré (AAAI 2025) for demoiréing; plus 90°/180°/270° rotation. Group 2 (App. I) swaps in NAF-DPM (a diffusion-based document enhancer) for deblur and BGShadowNet for deshadow; results are within ~1 point (Qwen3.5-9B 71.6/55.6 vs 70.9/54.4; Gemini-3.1-Pro 84.3/80.0 vs 84.1/78.9). All tools run "on a single NVIDIA A6000 GPU" with "official open-source checkpoints and default inference scripts" — [arXiv HTML, §4.1, App. F, App. I](https://arxiv.org/html/2608.29037)
- **Forward model / measurement consistency: none.** The paper contains no forward operator, no data-consistency term, no posterior; restoration is a single deterministic tool call per step — [arXiv HTML](https://arxiv.org/html/2608.29037)
- **Comparison-Based Rollback (CBRb):** "provides the MLLM with the current question and the images before and after restoration, allowing it to compare the readability of question-relevant evidence. When restoration distorts or blurs the relevant text and makes the question more difficult to answer, the system triggers rollback ... disable it from the available tool list, and attempt to address other degradations." Loop = Phase A (Answerability-Guided Restoration) → Phase B (Comparison-Based Review) until answerable or all relevant tools disabled; a maximum-iteration cap T is set (numeric value rendered as math and not recoverable from the HTML) — [arXiv HTML, §3.1–3.2, App. B](https://arxiv.org/html/2608.29037)
- Context management: "Text-only" strategy (keeps tool decisions and quality assessments as text, drops intermediate images); Full Context costs 1.55× tokens for Qwen3.5-9B (29,439 vs 19,032) — [arXiv HTML, App. E](https://arxiv.org/html/2608.29037)
- **Benchmark:** WildDoc (EMNLP 2025), 3 subtasks (WildDocVQA/ANLS, WildChartQA/Acc, WildTableVQA/Acc) + Consistency (correct in all four capture conditions). "At the time of our evaluation, WildDoc was the only publicly available benchmark specifically designed for document VQA under real-world capture degradations" — [arXiv HTML, §4.1](https://arxiv.org/html/2608.29037)
- **Main results (avg score / consistency):** Qwen3.5-9B 68.5/49.7 → 71.6/55.6; Gemini-3.1-Pro 83.0/75.5 → 84.3/80.0. Additional models (Table 4): GPT-4o 51.6/31.9 → 57.9/43.7; Claude Sonnet 4.6 57.5/30.5 → 66.4/41.7; GPT-5.2 62.9/38.7 → 69.5/47.7; Qwen3.5-Plus 76.1/63.0 → 81.7/69.9; Doubao-2.0-Pro 76.5/63.5 → 78.4/66.4; Qwen3.5-27B 71.0/55.2 → 75.1/61.3 — [arXiv HTML, Tables 1 & 4](https://arxiv.org/html/2608.29037)
- **Strategy baselines (Table 2):** blind Pipeline (all 5 tools) hurts (Qwen 63.2–63.5; Gemini 79.0–79.5); MLLM-Judge (restore all MLLM-identified degradations, no rollback, ~2.5–2.8 tools) ≈ no gain (Qwen 67.7/68.5; Gemini 82.9/83.1); Human Expert (40 experts, question-agnostic, 2.35 tools) 71.8/56.3 and 84.0/79.7; Human Expert question-aware (1.55 tools) 72.2/57.1 and 84.5/80.4; DocIntent 1.69 tools → 71.6/55.6 and 1.16 tools → 84.3/80.0. Authors: "tool sequencing is not the key limitation" — [arXiv HTML, §4.3](https://arxiv.org/html/2608.29037)
- **Ablation (Table 3):** answerability prompt alone does nothing (Qwen 68.5→67.8; Gemini 83.0→82.9); +tool invocation (AGRes) 69.2/50.5 and 83.7/78.4; +CBRb 71.6/55.6 and 84.3/80.0. "For the less capable Qwen3.5-9B, AGRes brings limited gains, making CBRb more critical" — [arXiv HTML, §4.4](https://arxiv.org/html/2608.29037)
- **Answerability judgment vs difficulty (Table 6, direct answering only):** the MLLM's "Confident" subset scores above baseline and the "Forced" (needs-tool) subset below: GPT-4o 51.6 baseline, Confident 68.7, Forced 38.5; Gemini 83.0 / 85.9 / 79.5; Qwen3.5-9B 68.5 / 74.2 / 61.7. On the Forced subset DocIntent beats direct answering for every model (e.g., GPT-4o 38.5→49.8; Claude 46.4→62.4) — [arXiv HTML, App. D](https://arxiv.org/html/2608.29037)
- **Cost / latency:** no wall-clock latency reported. Token overhead per sample: Qwen3.5-9B 5,313 → 19,032; Gemini-3.1-Pro 2,376 → 6,106; GPT-4o 2,095 → 14,473. API cost per sample: Gemini-3.1-Pro 5,033 in / 1,073 out tokens ≈ $0.0394; Claude Sonnet 4.6 $0.0932; GPT-5.2 $0.0635. Tools per sample range 0.69 (Doubao) to ~2.0 (GPT-4o, GPT-5.2) — [arXiv HTML, App. G, Tables 10 & 14](https://arxiv.org/html/2608.29037)
- **Multiple restorations / answer uncertainty: no.** One tool output per call; no sampling; no entropy or confidence measure; repeated-run study (App. K) reports mean±std over 3 runs only to show stability (values rendered as math). Clean DocVQA: 95.3→94.7 (Qwen), 95.6→95.4 (Gemini), i.e., small harm on clean data — [arXiv HTML, App. K–L](https://arxiv.org/html/2608.29037)
- Stated limitations: "the system's performance is fundamentally limited by the capabilities of the underlying restoration tools" and "judgment capability depends on the intrinsic abilities of the underlying MLLM" — [arXiv HTML, Limitations](https://arxiv.org/html/2608.29037)
- Related-work positioning: cites Uni-DocRobust (ICML 2026, feature-level restoration) as the alternative ("improves robustness through feature restoration, whereas DocIntent selectively invokes image restoration tools") and cites RestoreAgent, AgenticIR, HybridAgent, Q-Agent, 4KAgent, TIR-Agent as natural-image agents that "pursue optimal quality" — [arXiv HTML, §2](https://arxiv.org/html/2608.29037)
- **Threat:** F1 **medium** (owns "answerability" wording and an MLLM self-judged answerable/forced split, but no posterior, no measurement, no entropy; document-only); F2 **low** (no hypothesis conditioning; the restorer is question-agnostic, only tool *selection* is question-aware); F3 **low** (external tools, no unified model).

### Inferences
- The decision rule "restore only when the question cannot be answered" is currently owned by DocIntent (prompted self-judgment) and by CLEAR's learned trigger; both are arXiv-only as of Sep 2026. A reviewer will cite DocIntent against any answerability framing, so the user's F1 must be positioned as *measuring* identifiability (posterior spread of answers) rather than *asking the MLLM* whether it can answer.
- DocIntent's own Table 6 (Confident vs Forced) is the closest thing to an identifiability split in the literature, but it is a single-model self-report with no ground truth on whether y determines the answer; that is the gap F1 fills.
- Restoration agents' "reflection/rollback" is quality-driven (IQA) in every venue-verified paper; DocIntent is the first to make rollback question-driven. None makes it *measurement*-driven.

## KQ2. Does any agent or unified model use a physics forward model, data consistency, or diffusion posterior sampling as a tool? Multiple restorations to estimate answer uncertainty?

### Takeaway
No. Across every catalogued agent and unified model, restoration is a black-box tool or a prompt-conditioned generation; none exposes a forward operator, enforces y = A(x), samples a posterior at inference, or aggregates multiple restorations into an answer distribution. The only physics-aware VLM works are restoration-only (DU-VLM estimates degradation parameters to steer a frozen diffusion restorer; RIRF diagnoses parameters of a compositional forward model; FAPE-IR proves posterior ker(H)-ambiguity for AR decoders) and none is venue-verified.

### Cited Findings
- Robust-U1 recovery is a rectified-flow generation "conditioned on a specific recovery prompt (e.g., 'Recover the clean version of this corrupted image')", trained to "denoise a noisy version of the clean latent conditioned on [the corrupted image]"; the paper describes this as learning "the inverse mapping" but there is no forward operator, no data-consistency term, and inference is a single 50-step deterministic decode (Table 9: "Rec. Steps 50"). Multiple trajectories are sampled *only during Flow-GRPO training* ("we sample a group of G trajectories using stochastic sampling (enabled by converting the deterministic ODE to an SDE)") — [arXiv HTML §3.1–3.2, App. B.2](https://arxiv.org/html/2606.08063)
- Robust-U1 explicitly defers physics: "Incorporating explicit models of corruption processes could enhance recovery precision. Future work could develop hybrid approaches that combine data-driven recovery with physics-based or statistical priors of specific corruption types (e.g., deblurring with estimated blur kernels, denoising with noise models)" — [arXiv HTML, App. H.2](https://arxiv.org/html/2606.08063)
- CLEAR removes pixel supervision entirely in its RL stage ("After Interleaved GRPO, pixel-level supervision is removed entirely and generation is driven solely by answer-correctness rewards"), i.e., it moves *away* from measurement fidelity; its SFT prompt template even instructs "Do NOT reveal or guess the answer at this stage" before restoration, which is the opposite of hypothesis-conditioned (F2) restoration — [arXiv HTML §4.5 and App. C](https://arxiv.org/html/2604.04780)
- CLEAR's failure case: "Generation improves overall quality but cannot recover the fine detail needed for the answer. The model identifies its uncertainty but guesses incorrectly" — uncertainty is noticed qualitatively, never quantified — [arXiv HTML, Fig. 12](https://arxiv.org/html/2604.04780)
- Robust-U1's hallucination taxonomy names "Type III: Over-sharpened — Overconfident details from ambiguous input — Unreadable license plate → sharp but fabricated number", and measures it only as an aggregate harmful-flip rate (4.1% of answers flipped correct→wrong vs clean-image answers; SFT-only 7.2%; BAGEL 15.6%) — [arXiv HTML, App. E.1, Tables 16–17](https://arxiv.org/html/2606.08063)
- DU-VLM ("Understanding Degradation with Vision Language Model", arXiv:2602.04565, **UNVERIFIED venue**) predicts hierarchical (type, parameter key, continuous physical value) tuples from "physical image formation models" (e.g., haze via atmospheric light and transmission) and "can serve as a zero-shot controller for pre-trained diffusion models"; restoration only, no QA — [arXiv](https://arxiv.org/abs/2602.04565)
- RIRF / "Reason and Restore" (arXiv:2604.09511, UNVERIFIED) diagnoses "degradation-specific physical or statistical parameters" of a compositional forward process ("degradations are usually forward process with known parameters") before restoration; restoration only — [arXiv](https://arxiv.org/abs/2604.09511)
- FAPE-IR (arXiv:2511.14099, UNVERIFIED) contains a formal argument that with a known operator H having nontrivial nullspace, "any deterministic AR predictor removes detail along [the ambiguity direction]" and "genuine posterior variability ±u (unobservable since Hu=0) is averaged out" — a theoretical statement of exactly the identifiability issue F1 targets, but applied to restoration quality, not answers — [arXiv](https://arxiv.org/abs/2511.14099)
- JarvisIR, AgenticIR, RestoreAgent, 4KAgent, Restore-R1, TIR-Agent, MAIR, Q-Agent, OPERA, SEAR, Causal-AgentIR all score candidates with NR/FR IQA ensembles (MANIQA, CLIP-IQA, MUSIQ, NIQE, ...) or an MLLM perceptual judge; no measurement term appears in any reward — [Restore-R1](https://arxiv.org/abs/2512.18599); [4KAgent](https://arxiv.org/abs/2507.07105); [OPERA](https://arxiv.org/abs/2605.22104)
- TaskGuard (arXiv:2609.08011, UNVERIFIED, Sep 2026) predicts *restoration utility* for a frozen detector from the "realized restoration residual" and detector sensitivity; it is task-conditioned but detection-only and not an MLLM/inverse-problem method — [arXiv](https://arxiv.org/abs/2609.08011)
- A web search for diffusion-posterior-sampling tools inside MLLM VQA agents returned nothing relevant (only dMLLM surveys and unrelated medical VQA) — [search](https://www.emergentmind.com/topics/diffusion-multi-modal-large-language-models-dmllms)

### Inferences
- F2 (per-hypothesis text-conditioned inverse solving with Bayes-factor selection) has no prior art in this literature; the nearest objects are CLEAR's explicit prohibition on guessing before restoration and DU-VLM's parameter-conditioned diffusion control (restoration-only).
- F1's mechanism (answer distribution over posterior samples) has no prior art; the closest quantitative artifacts are Robust-U1's harmful-flip rate and Reliable-TWI's text-token entropy.

### Gaps
- I could not check Restore-R1's or 4KAgent's full text for any hidden measurement term beyond the extracted reward descriptions; the abstracts and method sections show IQA/MLLM rewards only.
- Semantic Scholar rate-limited most calls; Robust-U1's citation list returned one paper (Remember-R1, arXiv:2608.01314, unrelated), and DocIntent's returned zero, so I cannot rule out very recent (Sep 2026) follow-ups.

## KQ3. Which unified models do self-recovery / generative reconstruction before reasoning, and is any measurement-constrained?

### Takeaway
Two: Robust-U1 (ICML 2026, BAGEL; SFT on ImageNet-C → Flow-GRPO with SSIM+CLIP rewards → joint reasoning over corrupted+recovered images) and CLEAR (arXiv-only, BAGEL; learned selective `<image_restore>` trigger, latent bridge instead of decode–re-encode, interleaved GRPO on answer correctness). Neither is measurement-constrained at inference. Related unified-model work (UARE, RecA, Thinking with Generated Images) reconstructs or imagines for generation quality, not for answering under degradation; Uni-DocRobust (ICML 2026) restores *features* inside the MLLM rather than pixels.

### Cited Findings

#### Robust-U1 — in depth
- Bibliographic: "Robust-U1: Can MLLMs Self-Recover Corrupted Visual Content for Robust Understanding?", Jiaqi Tang et al.; arXiv:2606.08063 (6 Jun 2026), comment "Accepted by ICML 2026"; listed on the ICML 2026 virtual site — [arXiv abs](https://arxiv.org/abs/2606.08063); [ICML virtual](https://icml.cc/virtual/2026/papers.html?filter=titles&search=Robust-U1). PMLR volume for ICML 2026 not yet located (proceedings.mlr.press v267 is ICML 2025) — [PMLR](https://proceedings.mlr.press/v267/).
- Formulation: corrupted image ỹ = D(x); "first reconstructs a recovered image through an approximate inverse of the corruption process"; final answer from a reasoning function over both the corrupted and recovered images — [arXiv HTML §3](https://arxiv.org/html/2606.08063)
- Stages: (I) SFT of BAGEL on ImageNet-C with a rectified-flow loss; (II) Flow-GRPO on Robust-R1's training data with SSIM reward + CLIP (TinyCLIP) cosine-similarity reward vs the *clean ground truth*; (III) SFT on Robust-R1 reasoning chains with interleaved [corrupted, recovered, query] — [arXiv HTML §3.1–3.3, §4](https://arxiv.org/html/2606.08063)
- **Measurement consistency at inference: none.** Recovery is unconditional on any forward model; rewards require paired clean targets (a reference-free variant with caption–image CLIP reward reaches only 0.6233 vs 0.7398, App. D.1) — [arXiv HTML App. D.1](https://arxiv.org/html/2606.08063)
- **App. B.2 latency (R-Bench, "Qwen2.5-VL-7B-class hardware"):** Standard MLLM 1.8 s, 18 GB, R-Bench 0.6204; Detect-then-Recover 24.6 s, 28 GB recovery / 20 GB understanding, 50 steps at 1.21 step/s, 0.7082; full Robust-U1 55.0 s, 33 GB / 23 GB, 0.7398. "all costs are dominated by the rectified-flow denoising loop (50 steps)" — [arXiv HTML App. B.2, Table 9](https://arxiv.org/html/2606.08063)
- **App. H.2 (future work):** four directions — efficient recovery architectures (distillation, fewer denoising steps), **"Integration with Corruption-Specific Priors ... physics-based or statistical priors of specific corruption types (e.g., deblurring with estimated blur kernels, denoising with noise models)"**, video, benchmarks — [arXiv HTML App. H.2](https://arxiv.org/html/2606.08063)
- Results: R-Bench overall 0.7398 vs BAGEL 0.5770, Robust-R1 0.5017, Qwen2.5-VL-3B 0.4845 — [arXiv HTML Table 1](https://arxiv.org/html/2606.08063)
- Mechanism analyses: SFT-only 0.5974, CoT-only 0.6199, SFT+RL only 0.6623, full 0.7398 (C.1); PSNR vs R-Bench decoupled — SFT lifts PSNR 14.37→20.88 dB but R-Bench only 0.5770→0.5974, RL adds ~0.6 dB PSNR yet R-Bench jumps to ~0.72–0.74 ("recovery supports reasoning only when it is task-aligned") (C.2); always-on recovery on clean inputs 0.7821→0.7865 (C.3) — [arXiv HTML App. C](https://arxiv.org/html/2606.08063)
- Hallucination: answers from recovered vs clean image agree 92.3%; harmful flips 4.1%; beneficial 0.8% — [arXiv HTML App. E.1](https://arxiv.org/html/2606.08063)
- S2 lists 1 citing paper (Remember-R1) as of query; no follow-up adds measurement consistency — [S2](https://api.semanticscholar.org/graph/v1/paper/arXiv:2606.08063/citations?fields=title,venue,year,externalIds&limit=500)
- **Threat:** F3 **high** (owns "self-recovery in a unified MLLM", has an internal-vs-external table, and names physics priors as its own next step); F1 **low-medium** (Type-III over-sharpening and harmful-flip rate are the only uncertainty signals; no posterior); F2 **none**.

#### CLEAR (arXiv-only, UNVERIFIED venue; the second self-recovery paper)
- "CLEAR: Unlocking Generative Potential for Degraded Image Understanding in Unified Multimodal Models", Xiangzhao Hao et al., arXiv:2604.04780 (Apr 2026), no venue comment, no OpenReview hit — [arXiv](https://arxiv.org/abs/2604.04780)
- Mechanism: BAGEL base; SFT teaches a "generate-then-answer" pattern where the model may emit `<image_restore>` (multi-step denoising to a VAE latent); a Latent Representation Bridge injects the generated latent directly into the reasoning context ("latent reasoning") instead of decode→re-encode; Interleaved GRPO optimizes text tokens with GRPO and the denoising step with Flow-GRPO under an LLM-judged answer-correctness reward — [arXiv HTML §3](https://arxiv.org/html/2604.04780)
- Results (MMD-Bench Hard, 6 benchmarks): Bagel 60.15 → CLEAR-SFT 63.42 → CLEAR-RL 65.26; text-only CoT 60.02 ("fine-grained visual information destroyed by degradation cannot be recovered through language-level reasoning alone"); R-Bench: restoration model [4] + Bagel 65.05 vs Bagel 61.64 vs CLEAR-RL 67.07 — [arXiv HTML §4.2](https://arxiv.org/html/2604.04780)
- Selective triggering: generation rate 5.2% (low) / 12.2% (mid) / 36.4% (high severity); MMVP 46.6%, RealWorldQA 41.7%; "Inference time closely tracks the triggering rate" (absolute times in App. Table 11, not extracted) — [arXiv HTML §4.5](https://arxiv.org/html/2604.04780)
- Latent-substitution ablation: replacing the generated latent with the degraded image's own latent drops hard-avg 64.96 → 62.06, "confirms that the denoising process recovers visual structure absent from the degraded input" — [arXiv HTML §4.4](https://arxiv.org/html/2604.04780)
- Unified models without this training (Bagel, Janus-Pro, Emu3) "degrade significantly, confirming that existing generative pathways do not spontaneously contribute to robustness" — [arXiv HTML §4.2](https://arxiv.org/html/2604.04780)
- **Threat:** F3 **high** (selective, answer-reward-shaped self-recovery in BAGEL with an external-restoration comparison; would be cited against F3 even if unpublished); F1 **medium** (learned "assess sufficiency" trigger, but no posterior/entropy); F2 **low**.

#### Other unified / reconstruction-as-auxiliary works
- **Uni-DocRobust** — Yuxuan Zhou et al.; ICML 2026 (OpenReview ErZRlWv8kZ "ICML 2026 regular"; ICML virtual site); "Universal Plug-and-Play Robustness Enhancement for Multi-modal LLMs via Feature Restoration"; restores *features* not pixels; dataset figures (189,771 clean/corrupted pairs, 417,502 QA pairs) come from a secondary summary (Lacuna) and are **not verified from the paper** — [ICML virtual](https://icml.cc/virtual/2026/papers.html?filter=titles&search=Uni-DocRobust); [OpenReview search](https://api2.openreview.net/notes/search?term=Uni-DocRobust&source=forum); [Lacuna](https://lacuna.tiptreesystems.com/work/uni-docrobust-universal-plug-and-play-robustness-enhancement-for-multi-modal/wrk_38b8cc5ea5ff53fd45d6ae7e7d6a2316). Threat: F3 **medium** (an in-model restoration alternative that a reviewer may demand as a baseline; no pixel reconstruction, no measurement).
- **Robust-R1** — Jiaqi Tang et al.; AAAI 2026 Oral (arXiv comment); text-only degradation-aware reasoning chains with reward-driven "perceiving degradation parameters" and reasoning-depth scaling; no reconstruction — [arXiv:2512.17532](https://arxiv.org/abs/2512.17532). Threat: low (its "degradation parameters" are text, not a forward model).
- **UARE** (arXiv:2512.06750, UNVERIFIED) — Bagel-based unified IQA + restoration with "assessment-guided restoration"; no VQA — [arXiv](https://arxiv.org/abs/2512.06750). Threat: F3 low.
- **RecA (Reconstruction Alignment Improves Unified Multimodal Models)** — ICLR 2026 (arXiv comment; OpenReview ppQWp8yrm7 Poster); self-reconstruction from understanding embeddings to improve *generation/editing*, not robustness — [arXiv:2509.07295](https://arxiv.org/abs/2509.07295). Threat: low.
- **Thinking with Generated Images** — Ethan Chern et al., arXiv:2505.22525; **no venue found** (no arXiv comment, no OpenReview note; S2 shows 70 citing papers); generates intermediate visual subgoals / self-critiqued visual hypotheses for *generation* benchmarks (GenEval-style, "38% to 57%"), not degraded-input VQA — [arXiv](https://arxiv.org/abs/2505.22525); [S2 citations](https://api.semanticscholar.org/graph/v1/paper/arXiv:2505.22525/citations?fields=title,venue,year,externalIds&limit=500). Threat: F3 low (paradigm-level only).
- **Demystifying the Visual Quality Paradox** (arXiv:2506.15645, UNVERIFIED; OpenReview shows only a CoRR record) — finds "Off-the-shelf restoration pipelines fail to reconcile" MLLM preferences and proposes VQ-TTT (learnable pre-encoder kernel); this is restore-then-MLLM territory (other researchers) but is the strongest evidence that pixel-quality restoration ≠ answer utility — [arXiv](https://arxiv.org/abs/2506.15645). Threat: low; useful as motivation.
- **ROMA (Reinforcing Multimodal Reasoning Against Visual Degradation)**, arXiv:2605.09262, UNVERIFIED — RL robustness without reconstruction — [arXiv](https://arxiv.org/abs/2605.09262). Threat: none.

### Inferences
- Both self-recovery papers use BAGEL and both report that *task-aligned* rather than pixel-faithful recovery is what helps (Robust-U1 C.2; CLEAR §4.5 removes pixel loss). This cuts both ways for F3: a data-consistency term is a fidelity constraint, so F3 must show it improves answers (or answer calibration/identifiability), not PSNR.
- Neither paper conditions recovery on the question; CLEAR's trigger reads the question but its generation prompt is fixed. Question-conditioned or hypothesis-conditioned recovery (F2) is untouched.

### Gaps
- CLEAR's absolute inference times (App. Table 11) and the identity of restoration model "[4]" were not extracted.
- Uni-DocRobust's paper text was not read (OpenReview note fetch returned 403); its dataset figures are from a secondary source.
- No ICML 2026 PMLR volume was found to cite for Robust-U1/Uni-DocRobust; the arXiv comment line and icml.cc listing are the verification.

## KQ4. Does any work argue for/against reconstruction inside the reasoning model vs an external restorer, and with what evidence?

### Takeaway
Yes, three do, all favoring internal/coupled recovery, but the evidence is confounded: Robust-U1 compares its 7B-class BAGEL pipeline against *different* external restorers + Qwen2.5-VL-7B; CLEAR compares one external restorer + Bagel against CLEAR-RL on R-Bench (+2.02); Restore, Assess, Repeat and CoTIR argue against multi-module agents on latency/error-propagation grounds (restoration quality only). No paper runs the controlled comparison F3 proposes (same base model, same measurement, internal vs external, with/without data consistency).

### Cited Findings
- Robust-U1 App. B.1: external restorers as preprocessors before Qwen2.5-VL-7B on R-Bench — all-in-one DFPIR 0.5511, deblurring EVSSM 0.4581, denoising MambaIRv2 0.5459, dehazing BiLaLoRA 0.5371 — vs Robust-U1 0.7398; authors' explanation: "specialized modules ... require knowing the degradation type" and "even the all-in-one restoration model is optimized for perceptual quality rather than downstream understanding"; conclusion "the gain of Robust-U1 comes from task-aligned, internal recovery, not merely from cleaner images" — [arXiv HTML App. B.1, Table 8](https://arxiv.org/html/2606.08063). (Note: the base MLLM differs between arms — Qwen2.5-VL-7B vs BAGEL — so the comparison is not controlled.)
- Robust-U1 Table 1 also shows BAGEL alone (0.5770) already beats Qwen2.5-VL-3B (0.4845) and Robust-R1 (0.5017) on R-Bench, so part of the external-arm deficit is base-model choice — [arXiv HTML Table 1](https://arxiv.org/html/2606.08063)
- CLEAR §4.2(4): "A restoration model [4] followed by Bagel reaches 65.05, improving over the base Bagel (61.64) but still falling behind CLEAR-RL (67.07) by 2.02 points. The restoration model optimizes for pixel-level fidelity without coupling to the downstream reasoning task" — same base model in both arms, single external restorer, R-Bench only — [arXiv HTML](https://arxiv.org/html/2604.04780)
- CLEAR ablation: replacing the latent bridge with decode→re-encode during GRPO "limits the gain to 63.72" vs 65.26, "because the frozen decoder and encoder block answer-level credit from reaching the generation process"; bridge without GRPO ≈ SFT (63.11 vs 63.04) — evidence that the *optimization path*, not the representation, is what internal recovery buys — [arXiv HTML §4.4](https://arxiv.org/html/2604.04780)
- CLEAR also documents that plain unified models (Bagel, Janus-Pro, Emu3) get no robustness from their generative pathway "with no sign that their generative pathway contributes to robustness" — internal capacity is useless unless trained to be invoked — [arXiv HTML §4.2](https://arxiv.org/html/2604.04780)
- Uni-DocRobust (ICML 2026) argues for feature-level over pixel-level restoration on efficiency grounds ("By focusing on restoration at the feature level rather than the pixel level ... computationally efficient") — secondary-source summary, not verified from the paper — [Lacuna summary](https://lacuna.tiptreesystems.com/work/uni-docrobust-universal-plug-and-play-robustness-enhancement-for-multi-modal/wrk_38b8cc5ea5ff53fd45d6ae7e7d6a2316)
- Restore, Assess, Repeat (CVPR 2026) argues agentic tool pipelines "are cumbersome and slow" and that "even when the IQA explicitly identifies image degradations, final performance is still limited by the availability of a corresponding restoration tool and proper execution"; its latent-integrated model is "11.27× faster" — restoration-quality evidence only — [arXiv:2603.26385](https://arxiv.org/abs/2603.26385)
- CoTIR (arXiv:2606.17557, UNVERIFIED) argues multi-round CoT restoration has "(i) increased computational cost due to multi-step processing, and (ii) weak modeling of interactions between degradations" and internalizes the chain in FLUX.1-Kontext — restoration only — [arXiv](https://arxiv.org/abs/2606.17557)
- Restore-R1 (CVPR 2026 Findings) argues against reflection/rollback agents on latency ("inference time grows rapidly from Setting I (2 degradations) to Setting IV") — restoration only — [arXiv:2512.18599](https://arxiv.org/abs/2512.18599)
- DocIntent argues the opposite direction for documents — external tools orchestrated by a frozen MLLM beat blind or MLLM-judged full restoration, and "the critical factor ... is the intelligence of the orchestration strategy: determining when to restore, which tool to use, and whether to accept the results" — [arXiv HTML §5](https://arxiv.org/html/2608.29037)
- Robust-U1's detect-then-recover variant (0.7082 at 24.6 s vs always-on 0.7398 at 55.0 s) is the only published latency/accuracy trade-off for gated internal recovery — [arXiv HTML App. B.2](https://arxiv.org/html/2606.08063)

### Inferences
- The "internal beats external" claim rests on two tables (Robust-U1 Table 8, CLEAR §4.2) with confounds (base model; single restorer; no measurement constraint on either arm). A controlled study (F3) that holds base model, restorer capacity, and data-consistency fixed would be the first of its kind and directly tests Robust-U1's headline claim.
- Both papers attribute their advantage to task alignment, so F3's data-consistency term should be framed as a *complement* to task alignment (keeping the recovered image tethered to y while the reward shapes what is recovered), otherwise reviewers will point to Robust-U1 C.2 / CLEAR Table 4 as evidence that fidelity does not help.

### Gaps
- No work anywhere in the window runs internal vs external with the same base model *and* the same restoration prior; no work adds data consistency to a unified model's recovery.
- Restore-R1's absolute runtime numbers (Fig. 4) were not extracted.
